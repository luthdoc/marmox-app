# Story 6.4: Layout do Dashboard e Proteção de Rota

**Epic:** 6 — Dashboard
**Status:** completed

## User Story

As a marble company owner,
I want all dashboard pages to share a navigation bar with a logout option, and to be redirected to login if I'm not authenticated,
so that I can navigate the app and my data is protected from unauthenticated access.

## Acceptance Criteria

1. Existe `frontend/app/dashboard/layout.tsx` que envolve todas as rotas sob `/dashboard/`.
2. O layout verifica a sessão do usuário usando o server client do Supabase (JWT do usuário logado, não service key); usuário não autenticado é redirecionado para `/login`.
3. O layout renderiza uma barra de navegação superior com o nome "Marmax" e um botão "Sair".
4. O botão "Sair" chama `supabase.auth.signOut()` e redireciona para `/login`.
5. A navbar usa as cores do design system: fundo `canvas` (`#fff`), borda inferior `hairline` (`#e0e0e0`), sem sombra, sem gradiente.
6. O Supabase client usado na verificação de sessão do servidor usa o JWT do usuário logado (não service key) para que o RLS se aplique em todas as queries subsequentes.
7. A rota `/dashboard` (index) redireciona para `/dashboard/leads`.
8. O layout é responsivo: em mobile, o nome e o botão "Sair" cabem na mesma linha sem overflow.
9. `npm run typecheck` e `npm run lint` passam sem erros.

## Technical Notes

> Leia `node_modules/next/dist/docs/` antes de implementar — esta versão do Next.js tem breaking changes em layouts aninhados, Server Components e como `cookies()` / `headers()` funcionam. O comportamento de `redirect()` dentro de Server Components pode diferir do esperado.
>
> O sign-out requer um Client Component (usa evento de clique e chama o browser client). O layout pode ser um Server Component que verifica a sessão e renderiza um Client Component filho para a parte interativa da navbar.
>
> A verificação de sessão no servidor deve usar o server client factory de `frontend/lib/supabase-server.ts` (Story 6.1).
