# Story 6.2: Design Tokens e Componentes Base

**Epic:** 6 — Dashboard
**Status:** completed

## User Story

As a developer,
I want design tokens and base UI components aligned with the apple-DESIGN.md system,
so that all dashboard screens share a consistent visual language without duplicating styles.

## Acceptance Criteria

1. `frontend/app/globals.css` é atualizado com os tokens de cor do design system: `--color-canvas`, `--color-canvas-parchment`, `--color-ink`, `--color-ink-muted`, `--color-hairline`, mantendo `--color-action-blue: #0066cc`.
2. Body font-size está em 17px (não 16px), line-height 1.47, family `system-ui, -apple-system, sans-serif` com Inter como fallback.
3. Existe `frontend/components/ui/Button.tsx` com variante `primary` (pill, Action Blue, texto branco) e `utility` (border-radius sm/8px, borda hairline). Sem sombra.
4. Existe `frontend/components/ui/Card.tsx` com border-radius `18px`, fundo `canvas`, sem sombra.
5. Existe `frontend/components/ui/StatusBadge.tsx` que recebe `status: 'new' | 'qualifying' | 'qualified' | 'scheduled' | 'handoff' | 'cold'` e renderiza um badge com cor de texto diferenciada (sem usar segundo accent — usar variações de ink e action-blue).
6. Nenhum componente usa gradiente decorativo ou sombra em UI chrome.
7. `npm run typecheck` e `npm run lint` passam sem erros.

## Technical Notes

> Leia `node_modules/next/dist/docs/` antes de implementar — breaking changes nesta versão do Next.js afetam como arquivos de layout e componentes são importados.
>
> Tailwind v4 usa `@import "tailwindcss"` e tokens definidos em `@theme inline {}` — não usar `tailwind.config.js`. Novos tokens de cor devem ser adicionados dentro do bloco `@theme inline` existente em `globals.css`.
>
> Border radius do design system: pill = `9999px` para CTAs primários, lg = `18px` para cards, sm = `8px` para botões utilitários. Não usar `rounded-full` do Tailwind para cards.
