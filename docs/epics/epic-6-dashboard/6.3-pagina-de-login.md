# Story 6.3: Página de Login

**Epic:** 6 — Dashboard
**Status:** completed

## User Story

As a marble company owner,
I want to log in with my email and password,
so that I can access my dashboard securely.

## Acceptance Criteria

1. A rota `/login` existe e renderiza um formulário com campos `email` e `password` e um botão "Entrar".
2. O botão "Entrar" é do tipo `primary` (pill, Action Blue) conforme design system.
3. Ao submeter, o frontend chama `supabase.auth.signInWithPassword({ email, password })` usando o browser client (não a service key).
4. Todo input é validado antes de ser processado: email deve ser formato válido, password não pode ser vazio — erros de validação são exibidos inline abaixo do campo correspondente.
5. Erro de autenticação retornado pelo Supabase (ex: credenciais inválidas) é exibido como mensagem de erro visível na tela, sem exibir detalhes internos do Supabase ao usuário.
6. Login bem-sucedido redireciona o usuário para `/dashboard`.
7. Usuário já autenticado que acessa `/login` é redirecionado para `/dashboard` sem renderizar o formulário.
8. A página é responsiva e operável no celular (campos de input com largura adequada, botão full-width em mobile).
9. A página não contém gradientes decorativos nem sombras em UI chrome.

## Technical Notes

> Leia `node_modules/next/dist/docs/` antes de implementar — esta versão do Next.js tem breaking changes em como redirecionamentos e middleware funcionam. Verificar se `redirect()` de `next/navigation` se comporta como esperado em Client vs Server Components.
>
> O redirecionamento de usuário já autenticado (AC7) pode ser implementado via middleware do Next.js ou verificação no lado do servidor no layout/page — confirmar o padrão suportado nesta versão antes de escrever o código.
>
> O browser client de Supabase (Story 6.1) deve ser usado aqui. A sessão é persistida automaticamente via cookies pelo client.
