# Story 6.1: Setup do Supabase Client e Autenticação no Frontend

**Epic:** 6 — Dashboard
**Status:** completed

## User Story

As a developer,
I want a configured Supabase client that uses the logged-in user's JWT for all queries,
so that RLS is enforced automatically and no query ever bypasses tenant isolation.

## Acceptance Criteria

1. O pacote `@supabase/supabase-js` está instalado em `frontend/`.
2. Existe `frontend/lib/supabase.ts` que exporta um browser client criado com `createBrowserClient` (ou equivalente da versão instalada) usando `NEXT_PUBLIC_SUPABASE_URL` e `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
3. O client usa a sessão do usuário logado para injetar o JWT em todas as requisições — não usa a service key em nenhum momento no frontend.
4. Existe `frontend/lib/supabase-server.ts` que exporta uma factory para uso em Server Components/Route Handlers, criada com `createServerClient` e cookies da requisição atual.
5. As variáveis de ambiente `NEXT_PUBLIC_SUPABASE_URL` e `NEXT_PUBLIC_SUPABASE_ANON_KEY` estão documentadas em `frontend/.env.example`.
6. `npm run typecheck` e `npm run lint` passam sem erros.

## Technical Notes

> Leia `node_modules/next/dist/docs/` antes de implementar — breaking changes nesta versão do Next.js afetam como cookies e headers são lidos em Server Components e Route Handlers.
>
> Verificar se a versão de `@supabase/supabase-js` disponível expõe `createBrowserClient` ou apenas `createClient` — usar o que a versão instalada suporta. Se o projeto usar SSR, o pacote `@supabase/ssr` fornece `createBrowserClient` e `createServerClient`; verificar compatibilidade antes de adicionar.
>
> O client do servidor deve ler cookies via a API de cookies do Next.js disponível na versão instalada (pode ser `next/headers` com `cookies()` ou padrão diferente — confirmar na docs local).
