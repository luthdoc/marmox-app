# Story 6.6: Lista de Leads

**Epic:** 6 — Dashboard
**Status:** pending

## User Story

As a marble company owner,
I want to see a list of all my leads with name, service type, status, and last contact date,
so that I can quickly understand the state of my pipeline without opening each lead individually.

## Acceptance Criteria

1. A rota `/dashboard/leads` existe e exibe uma lista de leads do tenant autenticado.
2. O Supabase client usado na busca usa o JWT do usuário logado (não service key); nenhuma query bypassa o RLS.
3. O response contém apenas campos do tenant autenticado — RLS garante isolamento; o frontend não exibe dados de outros tenants.
4. Cada linha da lista exibe: nome do lead (`name`), tipo de serviço (`service_type`), status (`status`) e data do último contato (`last_contact_at` formatada como "DD/MM/AAAA HH:mm" em pt-BR).
5. O status é exibido via `StatusBadge` (Story 6.2) com diferenciação visual clara entre os 6 estados: `new`, `qualifying`, `qualified`, `scheduled`, `handoff`, `cold`.
6. A lista é ordenada por `last_contact_at` decrescente (mais recente primeiro).
7. Leads com `name` nulo exibem o telefone (`phone`) truncado no formato `+55 11 9****-XXXX` como fallback — os últimos 4 dígitos são visíveis, os do meio são mascarados.
8. Ao clicar em uma linha, o usuário é navegado para `/dashboard/leads/[id]`.
9. Estado vazio (sem leads) exibe mensagem "Nenhum lead ainda." centralizada.
10. A página é responsiva: em mobile, as colunas menos prioritárias (ex: `service_type`) podem ser ocultadas se necessário para caber na tela.
11. `npm run typecheck` e `npm run lint` passam sem erros.

## Technical Notes

> Leia `node_modules/next/dist/docs/` antes de implementar — breaking changes nesta versão afetam como dados são carregados e cacheados em Server Components.
>
> A busca pode ser feita em Server Component para rendering imediato. Campos selecionados na query: `id, name, phone, service_type, status, last_contact_at`.
>
> A máscara de telefone do AC7 deve ser aplicada apenas no frontend (não altera o dado armazenado). Implementar como função utilitária pura em `frontend/lib/format.ts`.
>
> Formatação de datas em pt-BR: usar `Intl.DateTimeFormat('pt-BR', { ... })` para evitar dependência de biblioteca de data.
